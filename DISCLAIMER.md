## Privacy and Git history

The current public branch is maintained with generic examples and should not intentionally contain unnecessary personal information, private appointment details, credentials, or secrets.

However, Git is versioned: text removed from the latest branch can remain visible in historical commits. Public commit-author metadata may also identify the GitHub account that made a commit.

Cleaning the current branch is therefore **not the same as rewriting repository history**.

If a historical commit contains information that must be permanently purged, the repository owner should use an appropriate history-rewrite workflow such as `git filter-repo`, force-push the rewritten history, and follow GitHub's sensitive-data removal guidance where necessary.

Do not rewrite public repository history casually: it changes commit SHAs and can disrupt forks, clones, open pull requests, and existing links.

For material that must have no historical association with an existing repository, publishing a newly created sanitized repository can be safer than attempting to preserve old history.
